# Grid Community Engagement

## Current Approach

**Post-launch:** Adoption should happen organically through GitHub Issues and Discussions.

Grid is a **platform/foundation mod** - other modders discover it, use it as a dependency, and contribute back through Issues/PRs.

---

## GitHub Engagement (TBD)

### Issues
- Bug reports
- Feature requests from modders building on Grid
- API questions

### Discussions
- General questions
- Show and tell (community builds)
- RFCs for major changes

**Strategy:** Figure this out as the community develops. Don't over-engineer upfront.

---

## Opportunistic Content

### Hytale News Tie-ins
When Hytale releases major updates, consider posting:
- "Grid now supports X"
- Compatibility announcements
- New features enabled by Hytale updates

### Collaboration Posts
If other modders integrate with Grid:
- Showcase the integration
- Cross-promote on relevant channels
- (Figure out specifics when it happens)

---

## Long-Term Sustainability

### Avoiding Burnout
- Release when ready — quality over dates
- Automate what you can (GitHub Actions for builds/testing)
- Set clear boundaries on response times

### Community-Driven Features
- Public roadmap (GitHub Projects) - consider later
- Let community vote on priorities
- RFCs for major architectural changes

---

## What We're NOT Doing

- ❌ Content calendar / regular posting schedule
- ❌ Feature highlight posts
- ❌ Community builds tracking
- ❌ Roadmap update posts
- ❌ Dev blog

Keep it lightweight. Let the platform speak for itself.
